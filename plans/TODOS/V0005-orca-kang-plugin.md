# V0005 — Orca 용 kang 플러그인 설계

Orca 에서 `.kang` 문서를 읽기 쉽게 보여 주는 플러그인을 만든다. 플러그인은 두 가지 일을 한다.

1. `.kang` 문서를 마크다운처럼 렌더링해서 보여 준다.
2. 문서 사이의 import 연결을 Obsidian 의 Graph view 처럼 그래프로 보여 준다.

**관련 문서:** `V0001-kang-language-design.md` (문법), `V0004-kang-code-binding-and-dogfooding.md` (`kang index` 의 출력 방식)

---

## 왜 만드는가

Orca 는 `.kang` 파일을 원본 텍스트로 보여 준다. `keyword`, `import`, frontmatter 같은 문법 기호가 그대로 보인다. 그래서 사람이 문서를 읽기 불편하다.

kang 의 주 사용자는 LLM 에이전트다. 에이전트는 `kang show` 로 문서를 받는다. 이 플러그인의 사용자는 에이전트가 아니고 사람이다. 사람이 Orca 에서 문서를 직접 열어 읽을 때 이 플러그인을 쓴다.

## 목표

- `.kang` 파일을 Orca 에서 열면 렌더링된 화면이 먼저 보인다. 원본 보기는 Orca 가 기본으로 주는 토글로 연다.
- 렌더링 화면에서 다른 문서의 keyword 를 참조한 곳에 마우스를 올리면 그 정의가 보인다. 클릭하면 그 keyword 를 선언한 문서가 열린다.
- 그래프 화면에서 저장소의 모든 문서와 import 연결을 한 번에 본다. 점을 클릭하면 그 문서가 열린다.
- 문서가 바뀌면 `kang build` 한 번으로 그래프가 최신이 된다.

## 목표가 아닌 것

- 렌더링 화면에서 편집하기. 렌더링 화면은 읽기 전용이다. 편집은 Orca 의 원본 보기에서 한다.
- 컴파일 진단 보여 주기. 진단은 `kang build` 가 터미널에 출력한다.
- 그래프에서 "지금 연 문서" 강조하기. 아래 제약 2 때문에 정확히 할 수 없다.
- keyword 나 topic 을 그래프의 점으로 쓰기. 점은 문서 하나다.
- Orca 플러그인 카탈로그에 공개하기. 지금은 이 저장소 폴더에서 직접 설치한다.

## 실패로 보는 것

- 렌더링 화면이 원본과 다른 뜻을 보여 준다. 예를 들어 import 한 keyword 의 정의를 다른 문서의 것으로 보여 준다.
- 플러그인이 `.kang` 파일 내용을 바꾼다.
- 그래프가 오래된 데이터를 보여 주는데, 사용자는 데이터가 오래되었다는 것을 알 수 없다.

## 확인된 Orca 제약 (Orca 1.4.253 에서 확인)

플러그인 작성 가이드(`orca skills get orca-plugin-authoring`)와 타입 파일(`/Applications/Orca.app/Contents/Resources/plugins/types/orca-frame.d.ts`)에서 확인했다.

1. **custom editor 는 파일 하나의 내용만 받는다.** 다른 파일은 읽지 못한다. Orca 에서 다른 파일을 여는 기능(`editor.open`)은 worker 에만 있다.
2. **custom editor 는 자기 파일의 경로를 모른다.** 편집기가 받는 문서 정보에는 version, readOnly, content 만 있다. 패널에도 "탭이 바뀌었다" 는 이벤트가 없다.
3. **편집기 탭은 항상 파일 하나와 연결된다.** 파일이 없는 탭은 만들 수 없다.
4. **플러그인에는 네트워크가 없다.** 마크다운 렌더러와 그래프 라이브러리는 플러그인 폴더 안에 넣는다.
5. **`.json` 으로 끝나는 파일은 Orca 가 원본 보기로 연다.** `.kang.json` 처럼 확장자가 더 길면 Orca 는 플러그인 화면으로 바로 연다.
6. **worker 를 쓰는 플러그인은 설치할 때 사용자 승인이 필요하다.** worker 는 Node 로 실행된다.

## 결정된 것

### 그래프 인덱스 파일

- `kang build` 가 성공할 때마다 `.kang/graph.kang.json` 을 다시 쓴다. 사용자가 정했다.
- 파일에는 세 가지가 있다.
  - 문서 목록: 경로, description, 파일 내용의 해시
  - keyword 목록: 선언한 문서 경로, 이름, 정의
  - 연결 목록: import 하는 문서, import 되는 문서, import 한 심볼 이름들
- **제 결정:** build 가 컴파일 error 로 끝나면 파일을 쓰지 않는다. `kang index` 와 같은 규칙이다. 또 파일에 만든 시각을 넣지 않는다. 같은 문서에서 항상 같은 바이트가 나와야 git 에 불필요한 변경이 생기지 않는다.
- **제 결정:** 이 저장소에서는 파일을 git 에 커밋한다. `.kang/index.tsv` 와 같은 방식이다. 출력은 문서 경로로 정렬한다.
- **제 결정:** 이미 있는 파일이 kang 이 만든 파일로 보이지 않으면 덮어쓰지 않는다. 지금 `kang index`, `kang types` 가 쓰는 출력 함수(`main.rs` 의 `generate`)를 같이 쓴다.
- JSON 은 라이브러리 없이 직접 쓴다. V0001 §10.1 의 의존성 목록에 따르면 `kang` 크레이트의 외부 의존성은 `sha2` 하나뿐이다. YAML 출력도 직접 썼다.

### 그래프 화면

- 점은 문서 하나다. 화살표는 import 다. A 가 B 의 심볼을 import 하면 A 에서 B 로 가는 화살표를 그린다.
- 같은 두 문서 사이에 import 가 여러 개이면 화살표는 하나다. 화살표에 마우스를 올리면 심볼 목록이 보인다.
- 점 크기는 그 문서를 import 하는 문서의 수로 정한다.
- 점을 클릭하면 그 문서가 렌더링 화면으로 열린다.
- 드래그, 확대, 축소를 할 수 있다.
- 그래프 화면은 `.kang/graph.kang.json` 을 열면 보인다. 사용자가 정했다.

### 렌더링 화면

목업에서 사용자가 A 안을 골랐다.

- frontmatter 의 description 은 문서 맨 위에 인용 블록처럼 보여 준다.
- import 줄은 문서 위쪽에 칩으로 보여 준다. 칩에는 심볼 이름과 문서 경로가 있다.
- `keyword` 선언 줄은 용어 카드로 보여 준다. 굵은 이름과 정의가 있다.
- 본문에서 keyword 를 참조한 곳은 링크로 보여 준다. 마우스를 올리면 정의가 보이고, 클릭하면 그 keyword 를 선언한 문서가 열린다.
- topic 참조(`#topic`)도 링크로 보여 준다.
- 나머지 문법(`exception`, `cover`, `pending`, `uncoded`, `iknow`)은 원본 기호가 보이지 않게 표시만 한다. 표시 방법은 만드는 사람이 정한다.
- 나머지 본문은 일반 마크다운으로 렌더링한다.
- Orca 의 밝은 테마와 어두운 테마를 따른다.

### 플러그인 구조

- 이 저장소 안에 둔다. 사용자가 정했다.
- **제 결정:** 위치는 저장소 루트의 `orca-plugin/` 이다. 플러그인 id 는 `kang` 이다. `orca-` 로 시작하는 id 는 Orca 가 예약했다.
- 이 저장소 폴더에서 직접 설치한다(`orca plugin install ./orca-plugin`). 사용자가 정했다.
- 필요한 부분은 세 개다.
  - custom editor 하나: `.kang` 파일을 렌더링 화면으로 연다.
  - custom editor 하나: `.kang.json` 파일을 그래프 화면으로 연다.
  - worker 하나: 그래프 인덱스 파일을 읽어서 편집기에 준다. 편집기의 요청을 받아 문서를 연다.
- 렌더링 화면은 worker 에게서 그래프 인덱스를 받아 keyword 정의를 찾는다. 편집기는 다른 파일을 읽지 못하기 때문이다(제약 1).
- worker 는 지금 선택된 Orca workspace 의 경로에서 `.kang/graph.kang.json` 을 찾는다. 편집기가 자기 파일 경로를 모르기 때문이다(제약 2).
- **제 결정: 파일 내용의 해시로 문서를 찾는다.** 렌더링 화면은 받은 텍스트의 해시를 worker 에 보낸다. worker 는 인덱스에서 해시가 같은 문서를 찾는다. 이 방법으로 세 가지를 해결한다.
  - 편집기가 자기 경로를 몰라도 어떤 문서인지 안다(제약 2).
  - 같은 해시가 없으면, 인덱스가 오래되었거나 다른 저장소의 인덱스다. 이때는 keyword 정의와 링크를 보여 주지 않는다. 대신 "`kang build` 를 실행하세요" 라는 안내를 보여 준다. 그래서 틀린 정의를 보여 주지 않는다.
  - 그래프 화면도 같은 방법으로 오래된 데이터를 알린다. worker 가 각 문서 파일의 지금 해시와 인덱스의 해시를 비교한다. 다르면 그래프 위에 "인덱스가 오래되었습니다" 라는 안내를 보여 준다.
  - 해시를 계산하는 방법은 Rust 와 TypeScript 가 같아야 한다. 테스트로 두 쪽의 결과가 같은지 확인한다.
- worker 는 `kang` 바이너리를 실행하지 않는다. 인덱스 파일만 읽는다. 그래서 사용자 컴퓨터의 PATH 에 `kang` 이 없어도 화면이 동작한다.

## 만드는 사람이 정할 것

- 마크다운 렌더러와 그래프 라이브러리의 선택. 단, 둘 다 플러그인 폴더 안에 넣어야 한다(제약 4).
- 그래프 인덱스 JSON 의 정확한 필드 이름. 단, 위의 세 가지 목록은 모두 있어야 한다.
- `.kang` 문서를 렌더링용으로 파싱하는 방법. 문법은 V0001 이 기준이다.
- 인덱스 파일이 없을 때 보여 줄 안내 문구. "`kang build` 를 실행하세요" 같은 뜻이면 된다.
- 테스트 방법. Rust 쪽은 기존 테스트 방식을 따른다. 플러그인 쪽은 `orca plugin test`, `orca plugin check` 를 쓴다.

## 위험

- **worker 에서 `node:fs` 를 쓸 수 있는지 아직 확인하지 않았다.** 가이드에는 "worker 는 Node 로 실행되고 import 는 Node 처럼 찾는다" 고만 있다. 구현의 첫 단계에서 확인해야 한다. 쓸 수 없으면 이 설계의 worker 부분을 다시 정해야 한다.
- **지금 선택된 workspace 와 열린 파일의 저장소가 다를 수 있다.** 그러면 worker 가 다른 저장소의 인덱스를 읽는다. 해시로 문서를 찾으므로 틀린 정의는 보여 주지 않는다. 그러나 맞는 정의도 보이지 않는다. 같은 문서가 두 저장소에 똑같이 있으면 다른 저장소의 정의를 보여 줄 수 있다. 이 경우는 받아들인다.
- **내용이 똑같은 문서가 한 저장소에 두 개 있으면** 해시로 하나를 고를 수 없다. 이때는 정의를 보여 주지 않는다.
- **다른 세션이 저장소 문서의 문체를 고치는 중이다.** README, `crates/kang/src/skill.md`, `main.rs` 같은 파일이 바뀌고 있다. 구현은 그 작업이 커밋된 뒤의 내용을 기준으로 한다. 그 세션의 결과를 그대로 받아들인다.
