# ADR-0003: 지속되는 주소는 심볼로 지정한다. 줄 번호를 쓰지 않는다

**Load when:** `kang bless` 인자 형식, 진단의 `fix` 표현, 코드 애노테이션의 위치 지정을 설계할 때. 또는 "줄 번호로 가리키면 간단하다" 는 제안이 올 때.

- **Status**: accepted
- **Date**: 2026-08-05

## Context

`kang bless` 의 첫 설계는 `docs/A:12` 처럼 파일과 줄 번호로 갱신 대상을 지정했다. `kang build` 가 그 형식으로 출력하고 사용자가 그대로 넘기는 흐름이었다.

그런데 스펙이 정한 정상 워크플로는 "참조 문서를 실제로 고친 뒤 bless 한다" 이다. 문서를 고치면 줄이 밀린다. 밀린 상태에서 이전 build 출력을 넘기면 **엉뚱한 줄의 rev 핀을 조용히 갱신한다.** 실패가 조용해서 잘못된 핀이 검사를 통과한다.

같은 결함이 진단의 `fix` 에도 있다. 한 번의 build 가 fix 를 여러 개 내고 에이전트가 순차 적용하면, 첫 fix 가 줄을 밀어 두 번째 fix 의 줄 번호가 이미 틀린다.

## Decision

**지속되는 주소는 심볼로 지정한다.**

```
kang bless docs/B --import docs/A.`결제`
```

한 파일 안에서 같은 심볼을 두 번 import 하는 것은 이미 error(한 심볼에 두 alias 금지)이므로 심볼 주소는 유일하게 결정된다.

진단의 `fix` 도 같은 규칙을 따른다. 무엇을 고칠지는 심볼과 선언으로 지정하고, 줄 번호를 수정 지시의 좌표로 쓰지 않는다.

**진단의 `location` 은 예외다.** 사람과 LLM 이 "어디를 보라" 를 알아야 하므로 줄 번호를 표시한다. 이것은 그 순간의 파일 상태를 가리키는 **휘발성 표시**이지 나중에 되먹임되는 주소가 아니다. 구분 기준은 "이 값이 저장되거나 다음 명령의 인자가 되는가" 이다.

## Consequences

### Easier

- 문서를 고친 뒤 bless 해도 안전하다. 스펙이 정한 정상 워크플로가 실제로 동작한다.
- `kang build` 출력을 그대로 인자로 넘기는 성질이 유지되면서 조용한 오작동이 사라진다.
- fix 를 여러 개 순차 적용해도 서로를 무효화하지 않는다.

### Harder

- 주소 문자열이 길어진다. `docs/A:12` 보다 `docs/B --import docs/A.\`결제\`` 가 읽고 쓰기에 무겁다.
- 심볼 주소를 파싱하는 코드가 필요하다. 줄 번호 정수 파싱보다 복잡하다.

## Alternatives considered

**줄 번호 유지 + build 출력에 파일 해시를 함께 실어 stale 검출** — 문서가 바뀌면 bless 가 거부하게 만드는 안. 조용한 오작동은 막지만, 정상 워크플로("고친 뒤 bless")가 항상 거부당하므로 사용자가 build 를 다시 돌려야 한다. 문제를 옮길 뿐 없애지 않는다.
